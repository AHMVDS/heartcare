# HeartCare  — # HeartCare

A modern heart health dashboard for patient risk assessment and data analysis.

Implements the supplied PDF: dark red #991B1B and slate #334155, single-patient sidebar, XGBoost/LR selector, gauge, bulk CSV table, distribution chart, downloadable results, and the supplied 10-row sample.

## Important model status
The uploaded sample has no outcomes and no trained models were supplied. The included XGBoost and Logistic Regression models are trained ONLY on synthetic data generated by `train_demo.py`. Their scores are NOT clinical risks. There is no clinical validation, disease endpoint, prediction time horizon, or supported clinical use. Band thresholds are arbitrary demo settings. The sample records are used for interface testing, not model training.

Input unit assumptions: systolic blood pressure in mmHg, total cholesterol in mg/dL, BMI in kg/m²; age in whole years. Confirm these against the intended clinical model. Do not use real patient data on a public demo.

## Run locally (Python 3.12)

```sh
python -m venv .venv
# Linux/macOS:
source .venv/bin/activate
# Windows instead: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

The archive includes both `.joblib` models. `requirements.txt` records the tested environment. Regenerate models after changing scikit-learn or XGBoost versions with `python train_demo.py`. Only load trusted joblib files: deserialization can execute code.

## Deploy

Upload this folder to your own GitHub repository (including models and `.streamlit/config.toml`). In Streamlit Community Cloud, create an app pointing to that repository with `app.py` as the entry point, and use Python 3.12. The deployment service will supply the live URL. No external API keys are required. Alternatively build the included Dockerfile and expose port 8501.

This delivery has no hosted deployment URL: the current environment cannot publish a Python Streamlit server. A Streamlit-compatible hosting account is needed to complete that deliverable.

## Replace the demo with a real model

Supply trusted trained pipelines and their exact feature definitions, units, class mapping, preprocessing, disease endpoint/time horizon, validation results and approved thresholds. Alternatively supply appropriate labeled training data and define that target. Integrate these in `core.py`, verifying the positive-class probability and metadata, and revise the UI/model labels and thresholds only after validation. No real-risk claims can be made from these ten unlabeled rows.

## Validation

Run `python -m unittest discover -s tests -v`. Tests cover both models on every sample record, probability bounds, batch/single parity, missing columns and invalid inputs. UI tests exercise the single-patient form and sample bulk workflow.
